## 真正的根因：预览 webview 模块级 TDZ 崩溃（14:5x 最终定位）

前面"复用窗口 show 成功"等日志只是证明 Rust 侧正确显示了窗口，但 webview 内容从不渲染。
加了 JS→Rust 错误桥（`debug_log` 命令 + preview/index.html 内联 error-catcher）后，捕获到真实报错：

```
[preview-js] [error] Uncaught ReferenceError: Cannot access 'defaultSettings' before initialization
    @ http://localhost:1421/shared/store/settingsStore.js:6
```

### 根因
循环依赖：`settingsStore.js` → `settingsService.js` → `@shared/api`(barrel) → `previewWindow.js` → `settingsStore.js`。
`settingsStore` 第 10 行 `proxy({ ...defaultSettings })` 在模块求值期访问了 `defaultSettings`，
但此时 `settingsService`（被其导入）还没执行到第 14 行 `export const defaultSettings` 的定义，
于是 `defaultSettings` 处于 TDZ（暂时性死区），整个预览 webview 在 import 阶段就抛错、React 无法挂载 → 卡片永不渲染 → 表现为"悬浮窗不显示"。
主窗口不崩是因为入口 import 顺序恰好让 `settingsService` 先完整初始化（与预览入口顺序不同，所以踩中 TDZ）。

### 修复（已实施）
- 新建 `src/shared/services/defaultSettings.js`：把 `defaultSettings` 对象整体搬入这个**零依赖**模块。
- `settingsService.js`：改为 `import { defaultSettings } from './defaultSettings'` 并 `export { defaultSettings }`（re-export，旧调用方无需改）。
- `settingsStore.js`：`defaultSettings` 直接从这个零依赖模块导入；`loadSettingsFromBackend/saveSettingsToBackend` 仍来自 `settingsService`。
- 这样切除了 TDZ 循环：`defaultSettings` 来自独立、先行完整初始化的模块；`previewWindow.js` 只在函数体内访问 `settingsStore`，不会在模块顶层触碰 TDZ。

## 修复主窗四角缩放仍异常（16:5x）

用户实机反馈：主窗四角调整"还是有问题"。复查 `WindowResizeHandles.jsx` 并与正常工作的预览窗 `PreviewResizeHandles.jsx` 对比，定位两处根因。

### 根因
1. **事件类型选错（核心）**：主窗缩放用 `pointermove`/`pointerup`，预览窗用 `mousemove`/`mouseup`。
   鼠标按住拖动时 `pointermove` 在指针移出窗口后**不再触发**（无 pointer capture），
   而 `mousemove` 有隐式捕获、移出窗口也持续。后果：拖 nw/sw/ne 角（鼠标常移出窗口）时缩放卡死；
   且 `Resized` 事件停止后，Rust 侧 `edge_monitor` 的 400ms 抑制过期（`RESIZE_SUPPRESS_DURATION_MS`），
   把窗口吸附到屏幕边缘"跳走"。这与"四个角调整还有问题"完全吻合。
2. **手柄默认 `pointer-events-none`**：靠 hover 180ms 后才可点，快速按下会落到下层触发 `useWindowDrag` 把窗口拖动而非缩放。

### 修复
- 缩放事件由 `pointermove`/`pointerup` 改为 `mousemove`/`mouseup`（与预览窗一致）。
- `onMove` 内加 `if (e.buttons === 0) onUp()` 兜底，防止 mouseup 在窗口外释放时漏捕。
- 命中区可点性分级：`nw/sw/se` 角下方无交互按钮 → `alwaysActive:true`（始终 `pointer-events-auto`），避免快速按下误触发拖动；
  `ne`（右上角）下方是标题栏 pin/more 按钮 → 保留仅在悬停提示出现后可点，避免遮挡按钮。
- 命中区尺寸收到 18px（略大于 16px 触发区），减小对左上角搜索框的轻微遮挡。
- 拖拽松手仍显式 `saveWindowSize`（逻辑像素）持久化。

### 验证
- esbuild 单文件转译通过；`vite build` 通过（仅既有警告）。
- 沙箱无头环境无法弹 GUI，未实机验证交互；需用户本地重新 `tauri:dev`/运行新 exe 验证四角缩放。

### 经验（可复用）
- 无边框 Tauri 窗自管四角缩放**必须用 `mousemove`**（隐式捕获），绝不用 `pointermove`（移出窗口即停）。
- 有边缘吸附（edge snap）的窗口，自管 resize 必须持续触发 `Resized` 以维持 `RESIZE_SUPPRESS` 抑制，否则会被吸附跳走。
- 自管缩放手柄若需避让标题栏按钮，用 `alwaysActive` 分级（无按钮的角常驻、有按钮的角悬停门控），不要整体 `pointer-events-none`（会误触发窗口拖动）。
